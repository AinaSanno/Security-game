# インシデント・ゼロアワー

銀行を舞台にしたセキュリティインシデント体験RPGです。攻撃側のフロンティアAIに脆弱性を突かれ、**攻撃 → 特定 → 解決** の流れをIBM製品で乗り越えます。スマホとPCの両方で動きます。

## 遊び方

ビルド不要です。[`index.html`](index.html) をブラウザで開くか、静的ホスティング（GitHub Pagesなど）に置けば動きます。

```
cd seminar-site/security-rpg
python3 -m http.server 8000   # http://localhost:8000
```

## ステージ構成（全5ステージ / 約5分）

製品名に加えて、「何をしているか」「何のために使うか」を、画面の中で先に伝える作りにしています。

| # | フェーズ | タイトル | 体験すること | 登場IBM製品（目的） |
|---|---|---|---|---|
| 1 | 攻撃 | 静かな侵入 | 古いシステムと置きっぱなしの合鍵を突かれ、口座情報が持ち出される | - |
| 2 | 特定 | 何が起きたのか突き止める | 異常に気づき、警告をつなげ、入口の弱点を調べる | Instana（いつもと違う動きに気づく）<br>QRadar（攻撃の流れをつなげる）<br>Container Registry（入口の弱点を調べる） |
| 3 | 解決 | Concertで、直す順番を決める | 数百件の問題から、最優先の3つを選ぶ | **IBM Concert**（何から直すか決める） |
| 4 | 解決 | Vaultで、鍵を止めて守る | 漏れた鍵を無効にし、使い捨ての鍵に切り替える | **IBM HashiCorp Vault**（鍵を止めて守る） |
| 5 | 解決 | AIの再襲来 | 目的に合う製品を選んで、AIの攻撃を退ける | API Connect（入口でアクセスをさばく）<br>Security Verify Access（怪しいときだけ本人確認）<br>Storage Protect（壊れたデータを戻す） |

## ゲームの仕組み

- **信頼（HP）**: 誤答で減り、0でゲームオーバー。そのステージの最初からやり直せます。
- **流出件数**: 攻撃中に増え、ステージ4でVaultが鍵を無効化すると拡大が止まります。
- **図鑑**: 登場したIBM製品が登録されます。製品の役割を確認できます。
- 問題形式は、選択、複数選択（優先順位づけ）、並べ替え（流れ・手順）、ターン制バトルです。

## ファイル

- [`index.html`](index.html): 画面の骨組み
- [`style.css`](style.css): レスポンシブなダークテーマ（フェーズごとに色が変わります）
- [`game.js`](game.js): ゲームエンジンとシナリオ。`STAGES` と `PRODUCTS` を編集すれば内容を差し替えられます

## 注意

- 「IBM銀行」はゲーム上の**架空の銀行**です。攻撃AI、件数、危険度の数値も架空で、実際の攻撃手順は含みません。
- 製品説明はIBM公式ドキュメントの概要を参考にした学習用の要約です。IBM Concert、IBM HashiCorp Vaultについては、機能や画面構成が変わる可能性があるため、最新の情報は公式ドキュメントで確認してください。
